# Анализ данных пассажиров «Титаника» – интерактивный дашборд

Цель проекта – провести разведочный анализ данных (EDA) о пассажирах «Титаника», обработать сырые данные и построить информативный дашборд, который наглядно отражает ключевые закономерности выживаемости.

**Инструменты**:

- **Python (Jupyter Notebook)** – для загрузки, очистки, трансформации и обогащения данных.
- **Yandex DataLens** – для построения интерактивного дашборда (бесплатный, работает в браузере, не требует установки).

---

## 📊 Структура дашборда

**ссылка на Yandex Datalens:** https://us.datalens-front.cloud.yandex.net/row54q7y5k9oa

Дашборд построен так, чтобы пользователь мог быстро оценить общую картину, проверить гипотезы и углубиться в детали.

### 1. Верхние индикаторы
- Общее число пассажиров  
- Количество выживших  
- Количество погибших  

Эти три числа сразу дают масштаб трагедии и отвечают на главный вопрос «А что вообще произошло?».

### 2. Кольцевая диаграмма
- Соотношение выживших и погибших в процентах.  
Интуитивно понятный и визуально лёгкий способ показать долю каждого исхода.

### 3. Четыре столбчатые диаграммы
На каждой диаграмме по оси X – категория (например, пол, возрастная группа), а по Y – процент выживших и погибших внутри этой категории (два столбца).

- **Выживаемость по полу** – проверка гипотезы «женщины спасались первыми».
- **Выживаемость по возрасту** – видно, имели ли дети приоритет.
- **Выживаемость по размеру семьи** – одинокие, малая семья (2–3 чел.), большая семья (4+).
- **Выживаемость по классу** – социально-экономический фактор.

Группировка возраста и размера семьи сделана для избежания перегруженности и облегчения восприятия.

### 4. Точечная диаграмма «Возраст vs Стоимость билета» с окраской по выживанию
- Каждая точка – отдельный пассажир.  
- Позволяет увидеть кластеры (например, пожилые люди из 3‑го класса с низкими шансами) и выбросы (дорогие билеты, которые не спасли).

### 5. Комбинированная диаграмма «Процент пассажиров в классе / Процент выживших»
- Две линии на одном графике:  
  - доля всех пассажиров в каждом классе,  
  - доля выживших в каждом классе.  
- Мгновенно видна диспропорция – например, в 1‑м классе мало пассажиров, но много выживших.

### 6. Две таблицы
- **Таблица «Процент выживших по возрасту и полу»** – детализированная сводка, где строки – возрастные группы, столбцы – пол, в ячейках – процент выживших.  
- **Таблица исходных данных** – фрагмент сырой таблицы (первые строки) для прозрачности и возможности проверить расчёты.

### 7. Фильтры (расположены сверху)
- Возрастная группа
- Тип семьи (одинокий / малая / большая)
- Ценовая категория билета (Low / Medium / High / Very High)
- Пол
- Статус выживания (выжил / погиб)

Фильтры применяются ко всем визуализациям одновременно, обеспечивая согласованность анализа.

## 📁 Данные

Исходные данные взяты с Kaggle:
- `Titanic-Dataset.csv` – обучающая выборка (пассажиры с известным исходом)
- `tested.csv` – тестовая выборка (исход неизвестен, но в нашем случае мы его используем как дополнительные данные)

В процессе EDA оба файла были объединены в один датафрейм (1309 записей, 12 исходных столбцов).

## 🧹 Предобработка данных (EDA)

В ноутбуке `eda_titanic.ipynb` выполнены следующие шаги:

1. **Загрузка и объединение** двух файлов.
2. **Обработка пропусков**:
   - `Age` – заполнены медианой (`28` лет).
   - `Fare` – заполнены медианой.
   - `Embarked` – заполнены модой (`S`).
   - `Cabin` – удалён из‑за слишком большого процента пропусков (~77%).
3. **Создание новых признаков**:
   - `FamSize = SibSp + Parch + 1` (размер семьи с учётом самого пассажира).
   - `IsAlone = 1`, если `FamSize == 1`, иначе `0`.
   - `AgeGroup` – категории: `Child` (0–11), `Teen` (12–18), `Adult` (19–39), `Middle` (40–59), `Senior` (60+).
   - `FareBand` – на основе стоимости билета: `Low` (0–19.97), `Medium` (20.21–49.50), `High` (50–93.5), `Very High` (>106.4).
   - `FamType` – `Alone` (1), `Small Family` (2–3), `Large Family` (≥4).
4. **Проверка типов** – преобразование категориальных признаков в `category`.
5. **Проверка на дубликаты** – дубликатов нет.
6. **Сохранение** обработанного датасета в `titanic_for_dashboard.csv` для загрузки в Yandex DataLens.
